# web-net v0.8.0 - Alpha

**The API as it should freeze, checked against the integrations that exist.**

## Highlights

- **Integrations**: Luminess renders the example site's pages straight into the reply (`Cx::body_mut`); a gate implementation (gatekeeper-io's `impl web_net::Gate`) compiles and builds an application against 0.8 unchanged but for its version pin; form-net's alpha routes (a login form and an avatar upload, each with its CSRF token) run in web-net.
- **Typed rendering**: `Render` has a generic associated view type, so a compiled engine such as Luminess reads the application's own types directly (checked at boot, no conversion), and a dynamic engine keeps web-net's `View`. Views may borrow. Error pages come from `Render::error_page`. Agreed with the Luminess engine before the freeze.
- **Freeze review**: the structs web-net makes and callers read (`Event`, `Served`, `Classified`, `Problem`) are `#[non_exhaustive]`, so 1.x can add fields.
- **`Cx::next_path`**: a sign-in page's safe way to read where to go next.

## Compatibility

Engines add `type View<'a> = dyn View + 'a;` (the 0.7 behaviour) and move an `error/<status>` template to `error_page`; handlers of a dynamic engine call `cx.render_view(..)` for a `&dyn View`; the engine is set before routes. Code that built `Event`, `Served`, `Classified`, or `Problem` with a struct literal no longer compiles; reading their fields is unchanged.
