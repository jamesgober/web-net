# web-net v0.7.0 - Hardening

**Every named threat attacked, the path rules proved, whole requests fuzzed, and the defects that turned up fixed.**

## Highlights

- **Attack tests** (`tests/attacks.rs`): one per threat in the plan, T-1 to T-15, each must fail. `docs/SECURITY.md` lists every defence and where it is tested.
- **Property tests**: path normalization is idempotent and leaves no dot segment, empty segment, backslash, or control; every spelling of a path normalizes to one canonical path; decoding inverts the canonical encoding; route lookup is sound and complete against the plain definition.
- **Fuzzing** (`fuzz/`): `request` sends any bytes as requests on a keep-alive connection to an application with gates, groups, CSRF, forms, CORS, and hooks; `path` sends any request target and checks that a canonical redirect is never redirected again and that no spelling reaches a protected page. About two and a half hours per target across the fixes (the last half hour on the released code), over 40 million inputs in all, no findings; one early finding was a false positive in the harness itself. The full 24 hours per target is on the 0.9 list.
- **Fixes**, each with a regression test: a multipart CSRF token is now checked before the handler runs (0.4 checked it while the form was read, which let a handler that never read its body run first); a reply with a cookie is never `public`; the cacheability report needs web-net's own `Cache-Control` and no CORS policy; Windows 8.3 short names no longer reach dot files; a file that cannot be read is a clean 500; preflights list only the methods under the policy; an empty `Host` is a 421. Four more turned up after that (a changed file mid-download could end cleanly with the wrong bytes; a gate's clearing cookie could cancel a fresh sign-in; a handler's `public` header could go out beside a pre-session cookie; health paths under `TrailingSlash::Add`), all fixed too.
- **Gate cookies**: `Identity::set_cookie` (written on every exit of `App::respond`, once) and `Denial::with_cookie`.
- **An example site** (`examples/site.rs`, feature `uploads`): sessions with a pre-session id, sign-in with CSRF, an upload, static files, pages rendered by Luminess through the new `Cx::body_mut`.

## Compatibility

`Denial` is `Clone` but no longer `Copy`. `Identity` has a new provided method. `Cx::body` no longer refuses a multipart body (its token was checked before the handler). No other signature changed.

## What's next

0.8.0, the alpha: a gate implementation and a template engine in use from crates.io, and form-net's alpha routes running in web-net. 0.9.0, the beta: the pre-1.0 polish pass, 24-hour fuzz runs, benchmarks on a quiet machine, and the 1.0 readiness note.
