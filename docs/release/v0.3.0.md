# web-net v0.3.0 - Static files

**A site serves its files and pages with the right caching and security headers.**

## Highlights

- **Static files** (`Assets`), served before the gate and the router: strong `ETag` and `Last-Modified`, 304 for `If-None-Match` and `If-Modified-Since`, one byte range (206, 416) with `If-Range`, precompressed `.br` and `.gz` variants with their own tags and `Vary`, `Cache-Control` per mount, and files over 1 MiB sent in parts with no state held between them.
- **No way out of the folder**: the path is canonical before it gets here, segments that file systems read specially are refused on every platform (dot files, `:` for alternate data streams, a trailing dot or space, Windows device names), and the resolved path must stay under the resolved root, so a symbolic link cannot lead out. No directory listings.
- **Health paths**: `health("/healthz")` and `ready("/readyz", check)`.
- **Security headers by default** on every reply: a strict content security policy, frame denial, referrer and permissions policies, opener isolation, and HSTS on HTTPS (never for a development host). A handler's own field wins; `SecurityHeaders::none()` turns them off.
- **Cookies out** with `Cx::set_cookie` (cookie-net, re-exported) and a **304 fast path** for pages with `Cx::not_modified`.

## Compatibility

Replies now carry the default security headers; `SecurityHeaders::none()` restores 0.2's replies. No signature changed. New dependency: parse-net 0.9.2.
