# web-net v0.2.0 - Core

**A site answers real requests.** 0.2.0 is the core of the web layer on serve-net and the design lock: canonical URLs, sites and base paths, a compiled router, gate checkpoints, hooks, rendering through a typed view, and one path for every error.

## The request path

1. **site**: the host picks the site (421 for an unknown host, a redirect for an alias or to HTTPS); the base path is removed, so a site works installed in a folder.
2. **url**: the path is decoded once and re-encoded one way, dot segments removed, empty segments collapsed. A path spelled any other way is redirected to the canonical spelling, so two spellings never reach different routes. An encoded slash, a backslash, a control character, or bytes that are not UTF-8 are refused with 400.
3. **authenticate**, 4. **route** (404), 5. **method** (405 with `Allow`; `HEAD` and `OPTIONS` automatic), 6. **authorize**: every route declares `public()` or `allow(rule)`, or the application does not build.
7. **hooks and handler**: the handler receives a `Cx`, which only exists after the gate passed.
8. **render**: a `Render` engine reads a typed `View` by key; no JSON in between.
9. **errors**: one function, the engine's error template or a built-in page, a reference for the visitor, the details only in the events.

## Highlights

- `App::respond_identified` for a front layer that authenticates before the web layer; web-net still authorizes every route.
- `App::classify` tells a dispatcher which route will run and how it behaves, before admission.
- The reply a handler writes is held until it returns: an error or a panic never sends half of it.
- Redirects from handlers are site-relative only; repeated query names and ambiguous cookies are refused.
- Zero third-party runtime dependencies: serve-net and cookie-net.
